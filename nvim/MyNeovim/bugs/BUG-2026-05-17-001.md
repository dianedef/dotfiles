# BUG-2026-05-17-001

- Title: `Leader H` n'ouvre plus directement la cheat sheet
- Status: fixed-pending-retest
- Severity: medium
- First seen: 2026-05-17
- Next step: retester `Space` puis `Shift+h` dans NeoVim

## Story

- Actor: utilisateur NeoVim du dépôt
- Trigger: saisie de `<leader>H` pour afficher la fiche raccourcis
- Observed: un sous-menu apparaît au lieu d'ouvrir directement `Cheat Sheet.md`
- Expected: la cheat sheet s'ouvre immédiatement, avec le même comportement de fermeture qu'avant

## Diagnosis Notes

- 2026-05-17 UTC: la cheat sheet était mappée sur `<leader>h` dans `lua/config/keymaps.lua`.
- 2026-05-17 UTC: le préfixe `<leader>h` est aussi utilisé par plusieurs mappings enfants (`<leader>ha`, `<leader>hm`, `<leader>hw`, `<leader>hl`, `<leader>hc`, `<leader>hp`, `<leader>h1`, `<leader>h2`, `<leader>h3`).
- 2026-05-17 UTC: ce chevauchement fait de `<leader>h` un namespace pratique pour `which-key`, ce qui explique le sous-menu observé.

## Fix Attempts

- 2026-05-17 UTC
  - Files changed: `lua/config/keymaps.lua`
  - Hypothesis: exposer la cheat sheet sur `<leader>H` supprime l'ambiguïté avec le namespace `<leader>h` tout en gardant les sous-commandes existantes.
  - Result: mapping direct déplacé vers `<leader>H`; retest manuel NeoVim encore requis.
