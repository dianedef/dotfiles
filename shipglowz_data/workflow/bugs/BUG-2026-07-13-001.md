# Bug Record: BUG-2026-07-13-001

## Summary

- Title: Mail Intelligence Avante request inherits unsupported Codex model metadata
- Current status: `fixed-pending-verify`
- Severity: `medium`
- Owner: Diane
- Next command: `/107-sg-test --retest BUG-2026-07-13-001 in Mail Intelligence`

## Reproduction

- Preconditions:
  - Avante uses the ACP `codex` provider.
  - A saved Avante ACP session was originally created with `gpt-5.6-luna`.
- Steps:
  1. Open a Mail Intelligence source in Neovim.
  2. Invoke the AI analysis action.
  3. Observe the ACP response panel.

## Expected Behavior

- Mail Intelligence starts a supported, explicitly selected model and receives a response without metadata fallback.

## Observed Behavior

- Avante reloads the saved ACP session and `codex-acp` continues using its original `gpt-5.6-luna` model despite the new process-level `gpt-5.4-mini` override.

## Evidence

- The operator supplied a redacted screenshot containing the model warning and ACP error.
- The saved Avante history contains an `acp_session_id` created under `gpt-5.6-luna`; its latest user message already advertises `gpt-5.4-mini`, demonstrating the process/header and restored-session mismatch.
- `avante.api.ask()` has no request-level model option; the ACP subprocess inherits Codex configuration unless its command arguments override it.
- Installed versions during the final diagnosis: `avante.nvim` commit `2183acf`, `codex-acp 0.16.0`, `codex-cli 0.144.3`.
- A live sanitized ACP session created after the repair reported `gpt-5.4-mini` and answered `OK`.
