# BUG-2026-05-04-001: Avante crashes on invalid buffer after plugin reload

Status: fix-attempted
Severity: medium
Created UTC: 2026-05-04
Next step: `/sf-test --retest BUG-2026-05-04-001`

## User Story

As the dotfiles user, when Neovim reloads MyNeovim after plugin/config updates, Avante and lualine should survive stale buffer references so the editor does not spam scheduled Lua callback errors.

## Reproduction

- Open Neovim with the versioned `nvim/MyNeovim` config.
- Let lazy.nvim update/reload plugins after Avante and auto-session updates.
- Remove or reload plugin specs such as `yazi.lua` / `tfm.lua` while Avante has scheduled history work.

## Expected

- Avante saves or skips history work without crashing if the original code buffer was already closed.
- lualine refreshes the statusline without `section_color` nil errors.
- Deleted plugin specs stay deleted and do not break the editor reload.

## Observed

- Avante called `vim.api.nvim_buf_get_name(3)` from `avante.utils.root.get` after buffer `3` was invalid.
- The failure repeated through scheduled `Path.history.save(...)` callbacks.
- lualine failed during statusline refresh with `attempt to index local 'section_color' (a nil value)`.

## Evidence

- User report: stack traces from `~/.local/share/nvim/lazy/avante.nvim/lua/avante/utils/root.lua:203`, `avante/path.lua`, `avante/sidebar.lua`, and `lualine/utils/section.lua:67`.
- Local versions: `avante.nvim` commit `ffebe7ac68cf063876b7691f7f1724fd5cabc03b`; `lualine.nvim` commit `131a558e13f9f28b15cd235557150ccb23f89286`.
- Config files: `nvim/MyNeovim/lua/plugins/avante.lua`, `nvim/MyNeovim/lua/plugins/lualine.lua`.
