# BUG-2026-05-03-001: Neovim AI agents ask for confirmations despite autonomous user config

Status: fixed
Severity: medium
Created UTC: 2026-05-03
Next step: Shipped fix.

## User Story

As the dotfiles user, when launching Codex or Claude Code from Neovim, the agent should inherit the autonomous/no-confirmation policy configured for the user so coding flows do not stop on approval prompts.

## Reproduction

- Open Neovim with the versioned `nvim/MyNeovim` config.
- Launch Codex through `agentic.nvim` or Claude through `claudecode.nvim` / Snacks terminal mappings.
- Ask the agent to perform an action that normally triggers a confirmation.

## Expected

- Codex uses the user's `codex-acp` binary and `approval_policy = "never"`.
- Claude is launched with `--permission-mode bypassPermissions`.
- Versioned dotfiles mirror the current non-secret Codex and Claude settings.

## Observed

- Codex provider path was hardcoded to `/home/claude/.npm-global/bin/codex-acp`, which does not exist for the current `ubuntu` user.
- `codex/config.toml` still declared `approval_policy = "on-request"`.
- Claude Neovim launchers used plain `claude`, without an explicit permission mode.
- Versioned Claude settings did not mirror `~/.claude/settings.json`.
